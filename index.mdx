Reclack is billing infrastructure for stablecoin payments. Your customer signs
one bounded approval in the wallet they already use, and Reclack opens each
billing period, submits the collection onchain, follows the transaction to a
confirmed state, and tells your application what happened.

You can use as much or as little of it as you need. Some teams only create
checkout sessions. Others run their whole catalog, subscriptions, invoices and
metered usage through the API.

## What Reclack does

| Capability | What it gives you |
| --- | --- |
| Subscriptions | Recurring collection from one bounded wallet approval, with retries and reconciliation. |
| Hosted checkout | A payment page that lists the wallets a browser exposes and explains the approval in words. |
| Payment links | A shareable page selling a fixed price or an amount the payer names. |
| Invoices | Line items, a PDF, reminders, and a pay link that does not expire. |
| Usage billing | Metered plans billed in arrears on usage you record. |
| Customer portal | Your customers sign in with the wallet they paid from and handle their own billing. |
| Webhooks | Signed events for every state change, with retries and replay. |

## What Reclack does not do

Being clear about this early saves you an afternoon later.

<Warning>
Reclack is non-custodial. Payments move from your customer's wallet to a
settlement address you control. We never hold your funds, and we never ask a
merchant or a payer for a seed phrase or a private key.
</Warning>

A confirmed blockchain transaction is final. There is no chargeback mechanism
and we cannot reverse a settled payment. If you agree to refund a customer, you
send the funds back from an address you control.

## Base URL

```
https://api.reclack.com
```

Every endpoint in these docs is relative to that host. The same host serves
sandbox and live traffic. Which one you are talking to is decided by the API
key you present, not by the URL.

## Getting help

Write to [support@reclack.com](mailto:support@reclack.com) with the request id
from the response headers, or the `reference` of the object you were working
on. That is usually enough for us to find the exact call in the request logs.
