This walks through one complete payment in sandbox. Nothing here moves real
money, and the same calls work against live once you swap the key.

<Note>
You need a Reclack account and a sandbox API key. Create one in the dashboard
under **Developers**, then **API keys**. Sandbox keys start with
`rk_sandbox_`.
</Note>

<Steps>
  <Step title="Set your key">
    Export the key so the examples below can use it.

    ```bash
    export RECLACK_KEY="rk_sandbox_your_key_here"
    export RECLACK_API="https://api.reclack.com"
    ```
  </Step>

  <Step title="Create a product and a price">
    A product is what you sell. A price says how much it costs, how often it is
    billed, and on which networks it can settle. You can create both in one
    call.

    ```bash
    curl -X POST "$RECLACK_API/v1/products" \
      -H "Api-Key: $RECLACK_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "Pro Plan",
        "description": "Everything in Starter, plus priority support",
        "price": {
          "amount": "29.00",
          "cadence": "monthly",
          "networks": ["base"]
        }
      }'
    ```

    The response carries the product with its price nested inside. Keep the
    price id: it is what a checkout session is built from.
  </Step>

  <Step title="Create a customer">
    Customers are how payments, invoices and subscriptions stay attached to a
    person rather than to an address.

    ```bash
    curl -X POST "$RECLACK_API/v1/customers" \
      -H "Api-Key: $RECLACK_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "email": "dana@acme.dev",
        "name": "Dana Okafor",
        "external_id": "user_4821"
      }'
    ```

    `external_id` is your own identifier. Sending it means you can look a
    customer up later without storing our id.
  </Step>

  <Step title="Open a checkout session">
    A checkout session is a hosted page your customer opens to pay. Pass the
    price id and the networks you are willing to accept.

    ```bash
    curl -X POST "$RECLACK_API/v1/checkouts" \
      -H "Api-Key: $RECLACK_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "price_id": "price_2Pb8xk9",
        "networks": ["base"],
        "customer": { "email": "dana@acme.dev" },
        "expires_in": 3600,
        "metadata": { "plan": "pro" }
      }'
    ```

    The response includes a `url`. Open it in a browser to see exactly what
    your customer sees.
  </Step>

  <Step title="Pay it in sandbox">
    The hosted page lists the wallets your browser exposes. Connect one on a
    test network, approve the spending limit, and confirm the payment.

    Sandbox runs on test chains, so you need test funds rather than real ones.
    The page tells you which network it expects.
  </Step>

  <Step title="Listen for the result">
    Create a webhook endpoint in the dashboard, then wait for the events. A
    completed subscription checkout produces `checkout.completed`,
    `payment.succeeded` and `subscription.created`.

    ```bash
    curl "$RECLACK_API/v1/events" \
      -H "Api-Key: $RECLACK_KEY"
    ```

    That endpoint lists everything Reclack has emitted for your workspace, which
    is handy before your webhook handler exists.
  </Step>
</Steps>
