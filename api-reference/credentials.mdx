---
title: "API keys"
description: "Mint, list and revoke the keys your services use."
---

Keys are environment specific and carry permissions. See
[Authentication](/authentication) for how to send one and what the permissions
cover.

## Create a key

```http
POST /v1/credentials
```

| Parameter | Type | Required | Notes |
| --- | --- | --- | --- |
| `name` | string | Yes | What this key is for, such as `billing-worker`. |
| `environment` | string | Yes | `sandbox` or `live`. |
| `permissions` | array | No | The permissions this key carries. Defaults to the minimum. |

```bash
curl -X POST "https://api.reclack.com/v1/credentials" \
  -H "Authorization: Bearer $RECLACK_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "usage-reporter",
    "environment": "live",
    "permissions": ["usage:write", "subscriptions:read"]
  }'
```

```json 201 Created
{
  "data": {
    "id": "cred_7Fh2PqX9",
    "name": "usage-reporter",
    "environment": "live",
    "prefix": "rk_live_4Kd9",
    "secret": "rk_live_your_new_key_secret",
    "permissions": ["usage:write", "subscriptions:read"],
    "created_at": "2026-10-18T22:07:41Z"
  }
}
```

<Warning>
`secret` is returned once and never again. We store only a digest of it, so a
database dump yields nothing usable and we cannot show it to you later.
</Warning>

## List keys

```http
GET /v1/credentials
```

Returns each key's `prefix`, name, environment, permissions and when it was
last used. Secrets are never included.

## Revoke a key

```http
DELETE /v1/credentials/{credentialId}
```

Takes effect on the next request. Calls already in flight finish.

<Tip>
Revoke rather than reuse when a key may have been exposed. Minting a new one
costs a minute. Finding out later that an old key still works costs more.
</Tip>
