## Record usage

```http
POST /v1/subscriptions/{subscriptionId}/usage
```

Permission: `usage:write`

| Parameter | Type | Required | Notes |
| --- | --- | --- | --- |
| `quantity` | integer | Yes | Whole units of whatever you meter. |
| `idempotency_key` | string | Yes | Makes a retry safe. Derive it from the thing being reported. |
| `recorded_at` | string | No | RFC 3339. When the usage happened. Defaults to now. |
| `metadata` | object | No | Your own context, such as the meter name. |

```bash
curl -X POST "https://api.reclack.com/v1/subscriptions/sub_4Kd9/usage" \
  -H "Authorization: Bearer $RECLACK_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "quantity": 48210,
    "idempotency_key": "sub_4Kd9:2026-10-18T22:00",
    "recorded_at": "2026-10-18T22:00:00Z",
    "metadata": { "meter": "api_requests" }
  }'
```

```json 201 Created
{
  "data": {
    "id": "usg_9Kd2Zm",
    "subscription_id": "sub_4Kd9",
    "quantity": 48210,
    "idempotency_key": "sub_4Kd9:2026-10-18T22:00",
    "recorded_at": "2026-10-18T22:00:00Z",
    "created_at": "2026-10-18T22:00:04Z"
  }
}
```

## Errors

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `idempotency_key_required` | No key was sent. One is required so a retried report cannot bill twice. |
| 409 | `usage_record_exists` | A record with that key already exists. The original stands. |
| 404 | `subscription_not_found` | No subscription with that id in this environment. |

<Tip>
A 409 is the protection working, not a failure. Treat it as success in your
retry logic.
</Tip>

## Rate limits

This endpoint is throttled more generously than the dashboard endpoints,
because usage is reported by machines and often in bursts at period boundaries.
Batching a minute of usage into one record with a key derived from the minute
keeps you well inside the limit.
