Subscriptions are created by a completed recurring checkout rather than
directly through the API. See [Subscriptions](/guides/subscriptions) for the
lifecycle.

## List subscriptions

```http
GET /v1/subscriptions
```

Permission: `subscriptions:read`

```bash
curl "https://api.reclack.com/v1/subscriptions" \
  -H "Authorization: Bearer $RECLACK_KEY"
```

```json 200 OK
{
  "data": [
    {
      "id": "sub_4Kd9",
```

## Retrieve a subscription

```http
GET /v1/subscriptions/{subscriptionId}
```

Permission: `subscriptions:read`

## Fields

| Field | Meaning |
| --- | --- |
| `status` | `active`, `past_due`, `paused` or `cancelled`. |
| `mode` | `fixed` for a flat amount, `metered` for usage billing. |
| `amount` | The amount per period, as a decimal string. |
| `amount_atomic` | The same figure in the token's atomic units. |
| `cadence`, `interval_seconds` | How often a period opens. |
| `network`, `chain_id` | Where collections settle. |
| `contract_address`, `onchain_id` | The authorization backing the subscription. |
| `current_period_start` | When the open period began. |
| `next_charge_at` | When the next collection is due. |
| `ends_at` | Set once cancellation is scheduled or complete. |

## Cancelling

Cancellation belongs to the customer. When you allow it, they send it from
their own wallet through the [portal](/guides/customer-portal), and Reclack
confirms the chain agreed before marking the subscription cancelled. Your
application hears `subscription.cancelled`.
